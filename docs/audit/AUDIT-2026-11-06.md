# Audit report: usability, 6 Nov 2026 (summary of three audits)

Trigger: Harsh tested the real build with 0G back and said it was "not near" what a screen tutor should be. Three read-only
audits ran against the live product and the real 0G router. Details and evidence are in the three documents named below.

## Other bugs found by the audits
- `scripts/desktop-demo.ts` drops its first argument, so the documented command never asks a question unless `--app` is given.
- A browser as the front app gives only the browser's own controls and tab titles (including private tab titles) and no page body.
- Chat ids and ids leak into bubbles ("located at [b27]"); "what about the next one" rings two random links (the word-overlap
  "which one" logic fires on follow-ups).
- The extension ignores synthetic key events (isTrusted), so the old test recipe of dispatchEvent does nothing; use real key events.
- The README, DECISIONS 2, SPEC and DESKTOP.md say "no screenshot": they must be reworded if the opt-in screenshot is adopted.

## What is NOT broken (keep)
Sealed models in Private mode for every decision, the laya check on every pointer, the safe-stop when 0G is unreachable, the
receipts (verified live), the measured pointing eval (11/12 clear, 0 wrong points, 6/6 vague), the replay.

## Fix plan
docs/PLAN-TUTOR.md (work packages and order) and docs/TUTOR-INTERFACE.md (the frozen contract). Evaluation: a frozen per-class
eval on the real router (evals/tutor/), reported per class, plus a blind human rubric.

## Open decision for Harsh
Screenshot opt-in for visual questions (charts, images, diagrams): fixes questions text cannot, +1.2 s, sealed end-to-end
encrypted provider only, explicit button and visible chip, never stored. Needs his yes and README rewording.
